# DevScout Cleaner

一个面向 Windows 的 Rust 原生 GUI 清理工具。它借鉴现有 `devscout` 的目录删除与 Restart Manager 检测思路，并提供拖放目录、可重复扫描和分级注册表候选选择。

## 安全边界

- 只删除用户在 GUI 中输入并扫描通过的目录，不接受相对路径。
- 拒绝磁盘根目录、Windows、Program Files、用户目录和 `C:\ProgramData` 本身。
- 默认扫描后将候选项全部勾选，但真正删除前仍由用户逐项取消。
- 注册表扫描覆盖当前用户/本机的卸载项、`App Paths`，以及 `Software` 下多层路径和程序标识引用。
- 正确读取 `REG_SZ`、`REG_EXPAND_SZ`、`REG_MULTI_SZ` 注册表值，并能识别带引号和参数的卸载命令。
- 扫描信号包括目录名、目录内 EXE 名、注册表键名和注册表值内容；这比只查 `InstallLocation` 更接近程序卸载工具的“足迹”思路。
- 列表按“确定垃圾”和“可疑”分类；确定垃圾通常有卸载路径或卸载命令的强证据，可疑项仅有一般路径引用。
- 注册表候选显示 32 位/64 位视图，并按根键、视图和子键路径去重，合并同一键的多个匹配理由。
- 只有路径引用与目标目录匹配的键才会列为候选，不会递归删除任意注册表分支。
- 删除前默认启用注册表备份；关闭开关后仍可清理，但确认框会明确警告且不会生成备份。
- 备份 `.reg` 文件直接保存在 EXE 所在目录，不额外创建备份文件夹；文件名包含时间、目标目录名、序号、根键、32/64 位视图和名称。
- 可通过“打开备份目录”按钮快速进入 EXE 所在目录；使用 `reg.exe export` 备份具体键，备份失败则跳过该键。
- 删除失败时使用 Windows Restart Manager 检测占用进程，并进入受保护的强力删除流程。
- 如果普通删除失败，工具会自动对 Restart Manager 明确返回的占用进程执行 `taskkill /F /T` 后重试；不会终止系统核心进程、当前工具自身或未被检测到的进程。
- 如果 `explorer.exe` 是占用者，强力删除后会自动重新启动 Explorer。
- 窗口显示当前是否为管理员权限；普通用户仍可扫描，但部分文件和 HKLM 注册表项可能无法清理。

## 构建

在 Windows 的 Rust GNU 工具链环境中运行：

```powershell
$env:Path = 'D:\toss pc\rubbish-from-C\.cargo\bin;D:\toss pc\rubbish-from-C\msy64-rust-mingw\mingw64\bin;' + $env:Path
cargo build --release
```

产物：`target\release\devscout-cleaner.exe`

## 使用

1. 输入一个要删除的绝对目录并点击“扫描”。
2. 也可以直接从 Windows 文件管理器拖入文件夹；拖入会自动替换路径并清空旧扫描结果。
3. 检查目录统计和分组后的注册表候选清单，查看其 32/64 位视图，并取消勾选不想清理的项。
4. 根据需要保留“删除前备份注册表”开关；默认建议保持开启。
5. 点击“删除并清理”，确认提示；清理前可以点击“打开备份目录”查看已有备份。

路径输入框发生变化时，旧扫描结果会自动清空；因此可以反复拖放、编辑、扫描和取消操作，不会复用旧目录的结果。

扫描在后台线程执行，窗口在大目录或深度注册表搜索期间仍可响应拖放、编辑和重新扫描。扫描状态会显示目录统计、当前已搜索的注册表项数量，以及最终发现的候选数量；可以点击“取消扫描”主动停止；切换路径或重新扫描也会自动取消旧扫描并丢弃其过期结果。

备份文件会直接放在当前 EXE 所在目录。使用 Cargo 运行时就是 `target\debug` 或 `target\release` 目录；发布后的 EXE 放在哪里，`.reg` 文件就放在哪里。
